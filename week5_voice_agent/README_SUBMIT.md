## 1. 系统架构（语音链路）

`
▶ 用户按住 "🎤 按住说话" 按钮
       │
       ▼
  💻 电脑麦克风（Web 浏览器端，非 ESP32）
       │
       ▼
  Web Speech API — SpeechRecognition
       │
       ├── 成功 ──► 识别文字填入输入框
       │                  │
       │                  ▼
       │           POST /api/nlp（复用 Week 4 后端）
       │                  │
       │                  ├── tool_query_latest → DB 查询
       │                  └── tool_request_collection → 请求硬件采集
       │                  │
       │                  ▼
       │           JSON 返回结果
       │                  │
       │                  ▼
       │           speechSynthesis — 中文 TTS 播报
       │                  │
       │                  ▼
       │           🔊 扬声器朗读回复
       │
       ├── 静音 ──► "🔇 未检测到声音，请重试"
       ├── 识别失败 ──► "😅 抱歉，未能识别您的语音"
       └── 服务超时 ──► "⚠️ 设备无响应，采集失败"
`

**核心特征**：
- 全程在 Web 浏览器端完成语音识别和合成，零后端改动
- **文字输入始终可用**，语音为可选快捷方式
- 使用浏览器原生 API（Web Speech API），无需额外安装

                     😅 识别失败
                     ⏰ 录音超时
`

## 3. 网页测试用例（5 个场景）

### ① 查旧数据（保留旧时间） ✅
**操作**: 按住🎤 → 说 "查看 group01_esp32s3eye 的最新数据" → 松开  
**流程**: 录音中 → 识别结果 → 任务执行中 → 正在播报...  
**期望**: 前端填入文字并自动发送，TTS 朗读数据库最新数值；返回的数据时间与数据库中已有记录一致（保留旧时间，不造假）

### ② 重新采集（生成新 request_id） ✅
**操作**: 按住🎤 → 说 "帮 group01_esp32s3eye 重新采集一次" → 松开  
**流程**: 录音中 → 识别结果 → 任务执行中 → 正在播报...  
**期望**: TTS 播报采集成功结果，返回的 request_id 和采集时间均为最新生成，与旧记录不同

### ③ 静音检测 ✅
**操作**: 按住🎤 → 不说话 → 松开（或等待超时）  
**期望**: 状态条显示 "🔇 未检测到声音，请重试或改用文字输入"，2 秒后恢复待机

### ④ 断网无响应（防作弊） ✅
**操作**: 停止 Flask 服务 → 按住🎤 → 说 "查看最新数据" → 松开  
**流程**: 录音中 → 识别结果 → 任务执行中 → 显示 "⚠️ 服务无响应"  
**期望**: 状态条显示 "⚠️ 服务无响应" 错误提示；TTS 不播报，防期末考试时硬件断开导致死循环

### ⑤ 歧义反问 ✅
**操作**: 按住🎤 → 说 "查一下那个东西" → 松开  
**流程**: 录音中 → 识别结果 → 任务执行中 → 系统返回 "🤔 请问您要查的是什么设备的数据？"  
**期望**: 状态条显示 "⚡ 任务执行中..." 后正常显示回复；歧义场景不执行工具，不播报 TTS

## 4. 异常处理清单

| 异常场景 | 检测方式 | 用户提示 |
|----------|----------|----------|
| 浏览器不支持语音 | !window.SpeechRecognition && !window.webkitSpeechRecognition | ⚠️ 浏览器不支持语音识别，请改用文字输入 |
| 静音/无声 | recognition.onerror 的 no-speech 错误 | 🔇 未检测到声音，请重试或改用文字输入 |
| 识别失败 | recognition.onerror 的其他错误码 | 😅 抱歉，未能识别您的语音 ({code})，请重试或改用文字输入 |
| 录音超时 | 10s setTimeout | ⏰ 录音超时，请重试 |
| 服务无响应 | fetch 超时 / HTTP 非 2xx | ⚠️ 服务无响应: {error} |
| 采集失败 | 后端 d.success === false | ⚠️ 设备无响应，采集失败 |
| TTS 播报失败 | utterance.onerror | 静默降级，状态恢复待机 |

## 5. 音频来源说明

| 项目 | 说明 |
|------|------|
| **音频输入** | 💻 **电脑麦克风**（非 ESP32 硬件麦克风） |
| **音频输出** | 🔊 **电脑扬声器**（浏览器 speechSynthesis） |
| **处理位置** | 🌐 **Web 浏览器端**（纯 JavaScript，走 Web Speech API） |
| **识别引擎** | 浏览器内置语音识别（SpeechRecognition），语言 zh-CN |
| **语音合成** | 浏览器 speechSynthesis API，中文 TTS |
| **任务卡路径** | 🎯 **使用电脑音频备用路径** — 语音输入与输出均在 Web 浏览器端实现（电脑麦克风/扬声器），硬件端（ESP32-S3-EYE）未做改动，符合任务卡"使用电脑音频"的备用路径要求 |
| **后端改动** | **零改动** — 完全复用 Week 4 的 /api/nlp 接口 |
| **无需网络** | 语音识别依赖浏览器离线引擎或系统语音服务，TTS 使用系统自带语音包 |

`atch

## 9. 关键技术决策

| 决策 | 理由 |
|------|------|
| **浏览器端 STT/TTS** | 零后端改动，无需处理音频流，浏览器原生 API 跨平台稳定 |
| **按住说话模式** | 避免意外触发；松开自动停止并提交，确保体验可控 |
| **10s 录音超时** | 防止用户忘记松手导致长时间无效录音 |
| **文字输入始终保留** | 当堂验证要求，且语音识别失败时回退方案 |
| **回复播报 + 非回复不播报** | 歧义/错误/无响应等场景不触发 TTS，避免播报无用信息 |
| **状态条闭环** | 用户时刻了解当前语音链路进展，符合无障碍最佳实践 |
| **零改动 ESP32** | 完全遵守老师纪律，所有代码均在 Web 前端 |
