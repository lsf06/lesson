# 第17周：改进与个人项目迁移报告

## 1. 基于证据的代码改进（真实修改）

* **修改证据**：来源于第16周真实的同伴测试记录（1名用户因等待焦虑产生连点，1名用户误判降级横幅为报错）。
* **前端修改**：在 `requestCollection()` 中加入了 3 秒的倒计时视觉反馈，彻底消除了用户因等待导致的焦虑误触；将黄色横幅文案修改为更明确的“网络离线...已切换至本地安全推理”。
* **回归记录**：重启并加载 Flask 服务后校验页面渲染（`GET /` 返回 200），确认新文案已生效、旧文案无残留；另用 Node 桩环境模拟“网络卡顿 / 正常返回 / 禁用期连点”三条路径，倒计时 3s→2s→1s 与提前恢复均符合预期，原有 `request_id` 状态机（`PENDING → RECEIVED → COMPLETED`）未被改动。

## 2. 个人项目迁移方案（边缘 AI 健康监护）

* **迁移模块**：第 14 周实现的**环形缓存队列**与**双时间戳（original_ts / retransmit_ts）比对机制**。
* **输入替换**：原本系统采集的是三轴加速度 `(ax, ay, az)`，在个人项目中，将替换为 `MAX30102` 传感器采集的**心率数据（heart_rate）**。
* **业务价值**：心率是强时间相关数据。当设备在户外断网时，心率数据会存入环形队列。恢复网络补传时，由于带有 `original_ts`，前端会明确标注该心率是“补传的历史心率”，绝不会被系统误判为“当前实时心率”，从而避免了严重的医疗健康误导。
* **失败处理**：当断网时间过长导致缓存队列满（20条）时，系统会自动丢弃最旧的心率数据，保证最新数据优先上传，并在串口打印 `QUEUE FULL, dropped oldest record`（沿用现有固件 `cache_enqueue()` 的实际日志语义）。

## 3. 模块复用与自证

* **输入**：ESP32 读出的心率值。
* **状态**：`is_device_offline`（网络状态）与 `g_cache_count`（本地缓存数量）。
* **输出**：前端数据卡片上的“实时”或“📦 已接收（补传）”标签。
* **失败处理**：遇到服务器宕机时，系统不会崩溃，自动转入本地缓存并在后台持续重连。
